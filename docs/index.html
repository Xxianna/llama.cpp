llama.cpp-glm-fast

更好的 GLM-5.3-Flash 混合推理方案。A better hybrid-inference setup for GLM-5.3-Flash.

  • 混合推理：更低的显存需求Hybrid inference: much lower VRAM requirement
  • 修复对 GLM-5.3-Flash 1M 上下文和大 batch 叠加的支持，降低长输入对 PCIE 带宽的依赖Fixed GLM-5.3-Flash support for 1M context combined with large batches, reducing long inputs' dependence on PCIe bandwidth
  • 保留热门专家缓存机制，降低 cpu 计算量Keeps the hot-expert cache, reducing CPU compute
  • 分段选择 prefill、decode 计算方式，提高不同上下文背景下的速度Selects prefill/decode execution paths by shape, improving speed across context lengths

批大小 65,536 的设置依据：每趟流水线存在与 token 数无关的固定开销（激活专家权重的 PCIe 上传、CPU/GPU 调度边界），批越大摊得越薄——64 token 批 48 token/s，65,536 批 859 token/s。Why the 65,536-token batch: every pipeline pass pays fixed costs independent of token count (PCIe upload of the batch's activated expert weights, the CPU/GPU scheduling boundary); the larger the batch, the thinner they amortize — 48 token/s at a 64-token batch, 859 token/s at 65,536.

显存：1M 上下文全额预留（q8_0 KV）+ 专家缓存 + 视觉适配器，峰值 46.9 / 48 GB，且不随输入长度增长（69k–250k 实测恒定）。VRAM: full 1M-context reservation (q8_0 KV) + expert cache + vision adapter peaks at 46.9 / 48 GB, independent of input length (measured flat from 69k to 250k).

4. 优化内容4. Optimizations

4.1 上下文有界的选择内存4.1 Context-bounded selection memory

  • 索引打分分块：得分按（上下文块 × token 片）计算，滚动 top-k 归并；乘积门控让小负载保持单块路径。选择阶段峰值显存不再随 上下文 × 批 增长——1M 预留下 69k–250k 输入实测恒定，单块路径在 1M 外推 93 GB。Chunked indexer scoring: scores are computed in (context-chunk × token-tile) blocks with a running top-k merge; a product gate keeps small workloads on the monolithic path. Selection-stage peak memory stops growing with context × batch — measured flat from 69k to 250k inputs at full 1M reservation; the monolithic path extrapolates to 93 GB at 1M.
  • 逐 token 可见计数：以每 token 可见池计数向量取代 [池数 × token 数] 的稠密因果掩码输入，块掩码由 GPU 现算；消除 1M 上下文下数百 GB 的宿主侧掩码输入及其 GPU 副本。Per-token visibility counts: the dense [pools × tokens] causal-mask input becomes a per-token visible-pool count vector, with chunk masks computed on the GPU; removes hundreds of GB of host-side mask input and its GPU copies at 1M context.
  • 融合掩码块：单趟 GPU 核将因果掩码块直写为注意力布局，取代约 10 算子的张量链，掩码数据量 6 → 1 KB/token。Fused mask blocks: a single GPU pass writes the causal mask block directly in the attention layout, replacing a ~10-op tensor chain; mask traffic 6 → 1 KB/token.

4.2 Prefill 吞吐4.2 Prefill throughput

  • token 分块 scatter：大单序列批按 token 片执行 DSA 注意力——转储行映射索引、逐片稀疏 flash attention、逐片输出投影。绕开 gather 的 latent 搬运瓶颈：同卡 65k 批形下 gather 约 125 token/s，分块 scatter 643（关缓存）至 859（端到端）token/s。Token-tiled scatter: large single-sequence batches run DSA attention in token tiles — dump-row-mapped indices, per-tile sparse flash attention, per-tile output projection. Escapes the gather path's latent-copy wall: gather ≈ 125 token/s at the same 65k batch shape on this card, tiled scatter 643 (cache off) to 859 (end-to-end) token/s.
  • 全 KV 库 f16 转换缓存：量化 KV → f16 转换按整个 KV 库缓存而非每批重转，每个满批减少约 90 GiB 冗余转换流量。Whole-KV f16 conversion cache: the quantized-KV → f16 conversion for flash attention is cached for the whole KV store instead of being redone per batch, removing ~90 GiB of redundant conversion traffic per full batch.

4.3 规模稳定性与确定性（64k → 262k+）4.3 Scale stability and determinism (64k → 262k+)

  • 核分批发射：token/KV 维度超过 CUDA 网格轴上限（65,535）的核分批发射；262k 全上下文批稳定运行，此前 53k+ 批触发 CUDA invalid argument。Batched kernel launches wherever a token or KV dimension rides a CUDA grid axis capped at 65,535 — 262k full-context batches run stable (previously 53k+ batches hit CUDA invalid argument).
  • 分块两遍式专家 GEMM：批量量化矩阵乘按共享内存上限分块、两遍式刷写；53k+ 批不再触发共享内存断言与刷写错位。Tiled two-pass batched expert GEMM keeps per-call shared memory bounded — 53k+ batches no longer trip shared-memory assertions or flush misalignment.
  • MMVQ/MMQ 网格防护：批量输入 gridDim.z 溢出防护。上游级缺陷，任何模型在批量量化路径达此规模均会触发。MMVQ/MMQ grid guard against gridDim.z overflow on batched inputs — an upstream-level defect any model hits on batched quantized paths at these sizes.
  • 确定性 top-k：默认走分段 argsort 路径，规避 CCCL < 3.4.3 的 DeviceTopK 竞态（上游已确认）；选择结果逐次可复现。Deterministic top-k: defaults to the segmented-argsort path, avoiding the DeviceTopK race in CCCL < 3.4.3 (acknowledged upstream); selection is reproducible run to run.
  • 跨后端选择一致性：CPU/GPU 的 top-k 与 argsort 排序对齐，所有路径填充全部选择输入，图重分裂时恢复调度器绑定；分块与单块选择路径在任意规模下取值等价（250k 逐 token 验证）。Cross-backend selection parity: CPU and GPU top-k/argsort orderings are aligned, every selection input is filled on every path, and scheduler rebinding is restored when a graph re-splits — the chunked and monolithic selection paths are value-equivalent at any scale (verified token by token at 250k).
  • decode 逐 token 图复用：图复用检查识别稀疏路径的 1 元素哑元掩码，消除长上下文 decode 每 token 整图重建的固定开销；10 → 14.6–17.6 token/s（4k–262k）。Per-token graph reuse in decode: the graph-reuse check recognizes the sparse paths' 1-element dummy mask, removing the per-token full-graph rebuild fixed cost of long-context decode; 10 → 14.6–17.6 token/s (4k–262k).

4.4 MoE 混合流水线4.4 MoE hybrid pipeline

  • 专家链按 token 分块：路由专家计算链按 token 切分，解码规模激活不再占用整批缓冲；专家缓存与 65k 满批共存于 48 GB。Expert chain tiled by tokens: decode-scale activations no longer occupy the full-batch buffer; the expert cache coexists with full 65k batches inside 48 GB.
  • 宿主权重每图全量拷贝：多消费者共享的 CPU 驻留专家权重每图拷贝一次，分块执行始终读取完整权重，大批下无额外带宽代价。One full copy per graph for host-resident expert weights shared by several consumers: tiled execution always reads complete weights, with no bandwidth cost at these sizes.
  • 准入控制 + 动态上传前瞻（采纳自基线新线）：miss 专家须在 64 token 窗口内复现方可占槽，预测上传按实测链路带宽与层耗时定时；本机解码 14.9 → 15.5 token/s（+3.8%），短对话命中率 12% → 14%。Admission control + dynamic upload lookahead (adopted from the base's newer line): a missed expert must recur within a 64-token window before taking a slot, and predicted uploads are timed by measured link bandwidth vs layer time; decode here 14.9 → 15.5 token/s (+3.8%), short-chat hit rate 12% → 14%.
  • 短批缓存阈值：缓存专家就地路径的批上限由 31 提升至 512，消除短输入越过该线后约 9 token/s 的损失。Short-batch cache threshold: the in-place cached-expert batch limit raised from 31 to 512, removing the ~9 token/s loss short inputs suffered above that line.

4.5 兼容与工具4.5 Compatibility and tooling

  • GGUF 兼容：unsloth 系 GLM-5.3-Flash 量化发布（架构命名、KV 前缀、视觉适配器），五分片 Q4_K_M + mmproj 直接加载。GGUF compatibility: unsloth-family GLM-5.3-Flash quantized releases (architecture naming, KV prefixes, vision adapter) — the five-shard Q4_K_M + mmproj load directly.
  • 诊断工具：逐节点产后读回转储、分配规划活性转储、逐请求缓存换入换出日志；仅显式开启时生效，约 1.5 倍减速。Diagnostics: per-node post-eval dumps, allocation-plan liveness dumps, per-request cache churn logs; active only when explicitly enabled (~1.5× slowdown).
